# Plan: Redesign Existing User Organization Creation Flow to Match Onboarding UX

## Current State

### Two creation paths exist

| Path | Component | Backend Endpoint | Route |
|------|-----------|------------------|-------|
| **Existing user** | `frontend/src/pages/workspaces/CreateWorkspace.tsx` | `POST /api/v1/workspaces` → `createWorkspaceStandalone()` | `/workspaces/new`, `/organizations/new`, `/app/organizations/new` |
| **New user onboarding** | `frontend/src/pages/onboarding/OrganizationSetup.tsx` | `POST /api/v1/organizations` → `createOrganization()` | `/onboarding/organization` |

### Key difference: backend endpoints have different data models

- `POST /workspaces` expects: `name, slug, type, typeConfig, country, state, city, timezone, currency, phone, logoUrl, initialProduct` — and **enforces subscription/plan limits** via `entitlementService.checkWorkspaceCreationEntitlement()`.
- `POST /organizations` expects: `name, industry, country, timezone, website, size, logo` — and does **not** enforce plan limits at creation time. It also returns `onboarding.status` for the state machine.

Because subscription enforcement lives on `POST /workspaces`, the existing-user flow must continue using that endpoint.

---

## Goal

Make the **existing-user creation flow** (`/workspaces/new?product=inventory`) **look and feel exactly like the onboarding flow**, while:
- Preserving subscription/plan-limit enforcement
- Pre-selecting the product from the query string
- Skipping pricing/plan-selection steps
- Keeping backend endpoint `POST /api/v1/workspaces`

---

## Implementation Plan

### Step 1: Create a new form component with onboarding-style UX

**New file:** `frontend/src/pages/workspaces/CreateWorkspaceForm.tsx`

This component replaces the current `CreateWorkspace.tsx` UI. It will mirror the `OrganizationSetup.tsx` layout and visual style:

- Uses `OnboardingLayout` (or the same card/gradient styling) with a step-like header
- Multi-section form: **Organization Details**, **Primary Branch**, **Contact & Address**
- Same color scheme, spacing, typography, and component choices as `OrganizationSetup.tsx`

### Step 2: Define unified form schema

The form collects fields from **both** flows and maps them to the `POST /workspaces` endpoint:

| Form Field | Source | Backend Mapping |
|------------|--------|-----------------|
| `name` | Both | `name` |
| `industry` | Onboarding | Mapped to `type` via lookup table (e.g. "Retail & Commerce" → "business") |
| `country` | Both | `country` |
| `currency` | Both | `currency` |
| `timezone` | Onboarding | `timezone` |
| `website` | Onboarding | `settings.website` |
| `size` | Onboarding | `settings.size` |
| `branchName` | Onboarding | `settings.branchName` |
| `branchCode` | Onboarding | `settings.branchCode` |
| `phone` | Existing | `phone` |
| `email` | Existing | `settings.email` |
| `description` | Existing | `settings.description` |
| `state, city, street, lga, blockNumber, area, landmark, postalCode` | Existing | respective address fields |

**Industry → Type mapping:**
```ts
const INDUSTRY_TO_TYPE: Record<string, string> = {
  'Retail & Commerce': 'business',
  'Wholesale & Distribution': 'business',
  'Boutique & Fashion': 'business',
  'Pharmacy & Healthcare': 'business',
  'Supermarket & Groceries': 'business',
  'Software & Technology': 'team',
  'Financial Services & Fintech': 'team',
  'Manufacturing & Logistics': 'team',
  'Hospitality & Food Services': 'business',
  'Professional & Legal Services': 'team',
  'Other / General': 'other',
};
```

### Step 3: Handle product pre-selection from query params

- Read `?product=inventory` (or `?product=taskmanagement`) via `useSearchParams()`
- Default to `inventory` if missing
- After successful workspace creation, call `POST /workspaces/:id/products/:product/activate`
- Redirect to home: `?workspace_created=1&app=:product`

### Step 4: Preserve existing post-creation behavior

- `refreshSession()` after creation
- Same success toast and navigation pattern as current `CreateWorkspace.tsx`
- Keep plan-limit enforcement (already in `POST /workspaces`)

### Step 5: Update routing

**File:** `frontend/src/surfaces/launcher/App.tsx`

- Replace `<CreateWorkspace />` with `<CreateWorkspaceForm />` on all existing routes:
  - `/organizations/new`
  - `/app/organizations/new`
  - `/workspaces/new`
- No new routes needed; query param `?product=inventory` drives product selection

### Step 6: Remove or deprecate old component

- `CreateWorkspace.tsx` can be deleted after the new component is verified
- Update any imports in `App.tsx`

## Out of Scope

- No product catalog expansion beyond the pre-selected `?product=` value
